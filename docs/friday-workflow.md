# Friday workflow deployment

Apply `supabase/migrations/202610210002_friday_workflow.sql` to the existing Supabase database before deploying this version. It adds history dates, message kind and simulation fields, booking guards, notification triggers, and the `quick_visit` RPC. Existing patient and visit rows are retained. Fresh installations should apply both migrations in order; the original migration's active-visit index now uses date columns directly, fixing PostgreSQL's immutable-index restriction.

The Overview and Calendar use completed visit history plus each patient's editable follow-up interval. Add reserves a Friday immediately. Open a patient name for Complete, Reschedule, Cancel, History, and Send SMS. A completion requires confirmation, including after swiping left. Rescheduling offers available Fridays from today rather than applying another follow-up interval. A patient profile can schedule another date as a clinical override. Pending reminders and unused confirmation tokens are invalidated when a visit moves or closes.

Demo records persist in the browser under `dentaflow-workspace-v2`, shared by Overview, Calendar, Patients, and Messages. Reset demo clears only those fictional records. Production pages load only authenticated clinic data from Supabase. Reports no longer appears in navigation; its old URL redirects to Overview.

Live SMS requires `NEXT_PUBLIC_DEMO_MODE=false`, `MESSAGING_PROVIDER=http`, `MESSAGING_LIVE_ENABLED=true`, `SMS_API_URL`, `SMS_API_KEY`, and `SMS_SENDER_ID`. The clinic must also have `messaging_enabled=true` and `messaging_provider=http`, and the patient must consent without an opt-out. Otherwise the job is delivered to the mock inbox. The configured HTTP gateway must implement the documented adapter JSON contract and honor `idempotencyKey`; an accepted HTTP request is shown as sent, not delivered. No delivery webhook integration is assumed.

New appointment events attempt delivery immediately after the booking transaction. Future reminders remain queued for the existing daily `0 6 * * *` cron. Set `CRON_SECRET` in Vercel and apply the service-role-only job claim RPC. The cron route authenticates independently of browser sessions. Provider errors retry on subsequent runs up to the stored limit; failed manual jobs can be explicitly retried with Send SMS. A failed worker after claiming a job can leave it processing; inspect provider delivery status before recovering it to avoid duplicate sends.

Run `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build`. Tests include UI gestures, demo lifecycle behavior, provider selection, and actual migration/RPC execution using an isolated embedded PostgreSQL database. Live Supabase credentials and real SMS are not required for those tests.
